# Supabase hosts auth/sessions for the shared Android+Web account system, scoped to identity only

Decided 2026-09-23 (wayfinder ticket [#7](https://github.com/gtphdee07/HDTTools/issues/7), part of map [#3](https://github.com/gtphdee07/HDTTools/issues/3)). Supabase (bundled Postgres + Auth) hosts the shared account system's users/sessions/auth-identity — email+password plus Google/Apple OAuth. This confirms the original hosting research's leaning recommendation, but on narrower grounds: that research recommended Supabase *because* its bundled Postgres gave a natural home to an owned `entitlements`/`credit_balances` table under Option 1B/1C. [ADR-0003](0003-revenuecat-everywhere-plus-unified-scan-gating.md) locked Option 1A instead, which means no such table exists anywhere — Supabase's actual job here shrinks to auth/sessions only, with just a thin table mapping a Supabase user id to a RevenueCat `appUserID`.

Kept Supabase anyway rather than switching to a leaner auth-only vendor (e.g. Firebase Authentication): its bundled email+password + Google/Apple OAuth already matches the locked auth methods exactly, still removes the same ~1-2 week hand-rolled-auth estimate the original research flagged, costs nothing at this scale, and needs no separate hosting decision — a leaner vendor would still need the small identity-mapping table hosted somewhere else, trading one integration for two. Explicitly scoped to auth/session/identity only: Rig/History stay local/per-device, not synced through this system, matching the map's Destination (accounts/paywall, not data sync) unless a later, separate effort decides otherwise.

## Considered options

- **Firebase Authentication** (leaner, auth-only, no bundled database): rejected — same OAuth coverage, but the identity-mapping table would then need a home wherever the near-term Web hosting ticket ([#8](https://github.com/gtphdee07/HDTTools/issues/8)) lands, adding a second piece to operate instead of one.
- **Rig/History sync riding on this same database**: rejected for now, not permanently — kept out of scope to match the map's Destination; revisit as a separate effort if cross-device Rig/History sync is ever wanted.
- **Supabase Pro ($25/month) from day one**, to avoid the free tier's pause-after-7-days-idle behavior and get backups: rejected for now — the map's own educational-tier, downtime-tolerant framing accepts this risk on the free tier; upgrading later is a billing change, not an architecture change.
