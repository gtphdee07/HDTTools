# Ticket skills

Three skills wrap a ticket's `/mattpocock-skills:implement` run, so setting up a worktree, finishing and merging are each one command. `/implement` is user-invocation only (the harness blocks a skill or sub-agent from calling it), so the skills go before it, after it, and at the merge. They follow `docs/agents/session-handoff.md` and build on `docs/agents/worktree-setup.md`.

| Skill | Run where | Does | Script |
|---|---|---|---|
| `/ticket-start <N>` | main checkout | Checks the ticket (closed, open blocker, assignee, existing branch or worktree, Android emulator in use), assigns it to the owner, cuts `.claude/worktrees/ticket-<N>` from `MPSkills`, runs `scripts/worktree_setup.py --copy-env`, writes the directions, prints the paste-ready `/implement` prompt (command plus handoff line) | `scripts/ticket_start.py` |
| `/ticket-finish` | the ticket's worktree, after `/implement` | Confirms the tree is clean and committed, runs the session-level suites the ledger does not already show as passed at this tree (and records each pass), maps each acceptance criterion to a test, runs `/code-review`, files follow-ups, posts the `STATUS:` comment, deletes the scratch file, then asks whether to move the session's shell out of the worktree into the main checkout (so the merge can remove the folder) | `scripts/ticket_finish.py` |
| `/ticket-merge <N>` | main checkout | Re-verifies independently (diff, criterion-to-test, mutation spot-check, and a re-run only of the suites `ticket_merge.py verdicts` marks `rerun` because the ledger has no pass for the branch tip's tree; the merged tree is re-tested only when `ticket_merge.py baseline` says `MPSkills` moved since the ticket was cut), merges `--no-ff` into `MPSkills`, closes the issue with a criterion-to-test comment, removes the worktree and branch. Never pushes | `scripts/ticket_merge.py` |

A typical ticket: `/ticket-start 42`, start `claude` in the new worktree and paste the printed prompt (`/mattpocock-skills:implement #42` plus the handoff line) as its first message, then `/ticket-finish`, then back in the main checkout `/ticket-merge 42`. Each skill is `disable-model-invocation: true`: only you can start one.

## Where the skills live, and how to install them

They are committed at `.claude/skills/ticket-start/`, `ticket-finish/` and `ticket-merge/` (each a `SKILL.md`). Claude Code loads `.claude/skills/` in a project automatically, so a checkout or a new worktree has them with nothing to install. The rest of `.claude/skills/` is gitignored (locally-fetched payloads, pinned by `skills-lock.json`); `.gitignore` un-ignores only `ticket-*`. A new skill that should be committed needs its own exception there.

A worktree carries the skills as of the commit it was cut from, so a skill edited on `MPSkills` reaches a worktree only after that worktree merges it. To use them from another repository, copy the three directories to `~/.claude/skills/` (they assume this repo's scripts, so that is not recommended).

## Each suite runs once per tree

The same code used to be tested again at every step: `/implement` ran the full suite, `/ticket-finish` ran the planner at `--level issue` and then `--level session` (which contains the issue tests), and `/ticket-merge` re-ran the targeted tests on the commit `/ticket-finish` had just vouched for. Now a pass is remembered by the git **tree hash** of the code it ran against (`HEAD^{tree}`), in the verification ledger from #65 (`scripts/verification_ledger.py`, a local file in the shared git directory, never tracked). An amend or a merge commit that changes no content keeps the tree and so keeps the pass; any content change loses it.

- **Implement**: runs single test files and typechecks only; the `/ticket-start` handoff line says so. The full run is left to `/ticket-finish`.
- **Finish**: `ticket_finish.py suites` plans the **session level only** for the branch's diff against its merge-base with `MPSkills`, skips each suite the ledger shows as passed at the current tree, runs the rest and records each pass. After a review fix, a suite whose last pass was at an earlier tree is re-run only if a file it depends on changed between the two trees (when unsure it runs; a Python suite counts any changed file, since its tests also read web, Android, fixture and doc files, so the saving is for the Web, Scan Proxy and Android suites); the other passes are carried forward and marked `carried_from` in the ledger. `post` refuses a suite reported as skipped that the ledger does not show as passed at the tree.
- **Merge**: `ticket_merge.py verdicts <N>` prints `skip` or `rerun` for each suite at the branch tip's tree, and `rerun` for any suite without a recorded pass. The reviewer still reads the diff, traces each criterion to a test and does the mutation spot-check (which runs only the tests it names), and runs just the `rerun` suites. `baseline` and the moved-baseline run after the merge are unchanged.
- **Planner**: `uv run scripts/test_planner.py` marks each suite `already passed at <tree>` or `run` and ends with a `To run:` line that leaves out the passed ones. A dirty tree is never vouched for. `--since-verified` (#66) plans each context from the last commit the ledger holds for it at the chosen level instead of from `--base`, so committed but unverified work is still planned; a context with no ledger entry is planned from `--base`. A change to an interface's provider side also queues the contexts that share it, a change to a context queues the contexts that `depends_on` it, and docs-only changes plan nothing. Each context's static checks (typecheck, lint, dead code, coverage floor; #150) are its `session_end` command, listed beside its suites when its files change and recorded in the ledger like any suite; see [static-checks.md](static-checks.md).
- **Verification debt**: `uv run scripts/verification_debt.py` (#67) prints, per context, the files changed since the ledger's last session-level pass, the tests owed, and a context-level catch-up command once a context passes the size or age limit (`debt` in `scripts/test_planner_config.json`). It only prints and always exits 0; setup as a Claude Code SessionStart hook is in [verification-debt.md](verification-debt.md).
- **What counts as a pass**: only a recorded pass. A failed, skipped or declined-paid run, a missing ledger and an unreadable ledger all mean "run it", and a failed run also drops a pass held for the same tree. Device tests, stale External surfaces and paid suites are never run by finish or merge; they show as `not run here` or `manual`.

## What the scripts decide

The skills hold the judgement steps; the scripts hold the rules, and their logic is tested (`tests/test_ticket_start.py`, `test_ticket_finish.py`, `test_ticket_merge.py`, `test_ticket_skills.py`).

- **Start** stops, changing nothing, on any reason above. A ticket counts as Android when its title says so or its body names a path under `android/`; override with `--android` or `--not-android`. The emulator is busy when another open, assigned Android ticket exists; `--emulator-free M` excludes an assigned ticket that never uses it (#43's release gate says Android in its title). Blockers come from GitHub's native dependencies and the body's `## Blocked by` list; an unreadable blocker counts as open.
- **Start's setup check** is `scripts/worktree_setup.py` itself: it installs from the lockfiles, then reports which local-only files are missing (#83 built no separate doctor command).
- **Finish** refuses `STATUS: READY TO MERGE` when the tree is dirty, any suite in the report failed, no suite was recorded, an acceptance criterion has no named test, the branch has no commits ahead of `MPSkills`, or a commit carries `dashboard.svg`, `external_status.json` or an `.env*` file (the one exception is `web/.env.production`, the committed file of public `VITE_*` values; never put a secret in it). Acceptance criteria are read from the ticket's latest `## Agent Brief` comment (its `**Acceptance criteria:**` list, since `/triage` makes the brief the authoritative spec), and from the issue body (`## Acceptance criteria` or the bold label) only when no brief comment exists; if both exist the brief wins, and a brief that lists none means the ticket has none to prove. A ticket that lists owner decisions under `## Decisions` also needs a comment starting `DECISIONS` that records them (the session asks with `AskUserQuestion` and posts the answers; see `session-handoff.md`). A suite's `passed` must be a real true/false. `PARTIAL` and `BLOCKED` are always postable but must say what is not done. The git facts (branch, sha, worktree, pushed) are computed by the script, not taken from the report.
- **Merge** needs the main checkout on a clean `MPSkills`, a newest `STATUS:` comment of `READY TO MERGE` (`--allow-status` if the owner decides otherwise), and a `ticket-<N>` tip that still matches the sha that comment vouches for (later commits mean re-running `/ticket-finish`). A conflict aborts and changes nothing. `close` refuses an unmerged branch or a comment with no criterion table, and a worktree that will not remove is reported with the issue already closed: a Windows long path is finished off by the script (an empty folder still held by an open session is left with the `rmdir` to run afterwards), while modified or untracked files are listed by name, nothing is removed, and commit/discard/keep is the owner's call.

The pre-commit hook (`.githooks/pre-commit`) skips regenerating `dashboard.svg` on `ticket-*` branches, so a ticket's commits do not carry it. The hook path is shared by every worktree, so the skip applies once it is merged into `MPSkills`; until then, commit with `--no-verify` or drop the file from the commit.

Free suites only: `/ticket-finish` and `/ticket-merge` run a paid or live suite only when the owner has set a budget for it in that session.
